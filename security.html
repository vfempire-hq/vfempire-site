HOW WE STAY CLEAN

Two independent gates,
plus a quarterly audit.

Zero findings today is a snapshot. Staying at zero requires the mechanism to be automatic. Two enforcement layers plus an ongoing audit cadence keep the trend line flat.

GATE 1

Pre-commit hook (local)

Runs at git commit time on every contributor's machine. Refuses commits containing high-entropy secrets before they enter git history. Config lives at .pre-commit-config.yaml in every VF public repository.

GATE 2

GitHub Actions CI (backstop)

Runs on every push, every pull request, and every Monday 06:00 UTC. Full git-history scan, beyond the current tree. A finding blocks the PR merge. Config at .github/workflows/security-scan.yml.

REVIEW

Quarterly audit + version bump

Every quarter we bump gitleaks to the latest version + re-run against full history in every public repo. New rule patterns sometimes match on historical files that were fine under the previous ruleset; we fix those before the bump lands. We document the run in each product's quarterly transparency report.

ESCALATION

Incident response

If a finding ever lands in a merged commit, we assume the secret is compromised. Immediate rotation of the credential, history purge via git filter-repo, force-push under owner approval, post-mortem within 5 business days per Terms § 8.

THE WIDER POSTURE

Everything we say about security
is something you can independently check.

Secret-free public repositories are one property. Four others together define the security posture VF Empire ships every product against.

2-of-2 threshold signing.

Two operators in separated EU jurisdictions sign every firmware release + rule pack + signed manifest, with a 15-minute inspection window between signature and publish. A single compromised operator cannot ship a malicious release.

Verifiable via public transparency log per product
Reproducible builds.

Every VF product binary is byte-for-byte reproducible from public source. Third-party CI mirrors (Berlin + Reykjavik) build continuously and compare their output against ours. Divergence would be publicly detectable within hours.

Verifiable via public reproducibility receipts
Bug bounty · €500 – €25 000.

Tiered by severity. Real payouts, published quarterly with severity histogram. Coordinated disclosure with 90-day default window. Reporters credited unless anonymous. The programme is how we discover what we missed.

Report to security@vfempire.com. Public bounty portal launches with R·01.
Terms § 8 warranty.

Material privacy breach = automatic refund + public post-mortem within 5 business days. Enforceable in Malta courts. A contract clause backed by insurance-funded escrow.

Full clause at vfempire.com/terms
Warrant canary.

Every product publishes a canary refreshed every 30 days. If it stops updating, users know we have received a national-security order or gag warrant we cannot disclose.

Live at each product's /canary.txt
Permanence Guarantee.

If VF Empire ever discontinues a product, we release the source under a permissive open-source licence within 90 days. The last signed firmware remains verifiable in the transparency log forever. We document the sealed vault format in a public spec. Your data stays readable long after we stop building.

Full guarantee at vfempire.com/software
COMMON QUESTIONS

What buyers + auditors ask.

Why is the source public if you're selling the product?

Public source is what makes every other claim on this page checkable. Reproducible builds, independent audits and bug bounty scale all require it. The licence is proprietary; the source is public. Same posture as Bitwarden, Signal, Home Assistant, ProtonMail clients and Nextcloud.

Doesn't public source mean competitors just copy you?

Bitwarden is open, at over $100M ARR + growing. Signal is open, dominant in E2EE messaging. Home Assistant is FOSS, dominant in home automation. None of them lost to clones. The moat for trust-critical consumer products is brand + community + support + regulatory position. Public source is a competitive advantage in this category.

What's scanned + how deep?

Full git history in every public VF Empire repository: every deleted file, every squashed commit, every orphan branch. Gitleaks v8.24.2 runs approximately 150 rule patterns covering the standard universe of secret types (cloud provider keys, payment provider tokens, source control tokens, database URLs, private keys of various formats, JWT signing secrets, generic high-entropy strings). The scan runs on every push + every PR + weekly cron.

What happens if you find something in the future?

We rotate the leaked credential immediately (assume compromised) and purge history via git filter-repo, then force-push with owner approval. We publish a post-mortem at /post-mortems/{id} within 5 business days per Terms § 8. If a paying customer is materially affected, the refund is automatic under the warranty. Insurance covers any additional exposure.

What about the private repositories?

Seven currently: FileIT, FuelIT, Guardian Shield, VF Wallet, VF Legacy, VF Home, vf-certificates. All under the same pre-commit + CI gitleaks discipline, internal-only until launch. On each product's launch, we review whether to graduate the repo to public with proprietary licence + Permanence-Guarantee auto-conversion (the same posture as the four repos above).

Can I get involved in the security review?

Yes. Coordinated disclosure via security@vfempire.com; the public bounty portal launches with R·01. If you want to run your own reproducibility CI mirror as an independent third party, we welcome additional mirrors in EU jurisdictions; write to the same address.
