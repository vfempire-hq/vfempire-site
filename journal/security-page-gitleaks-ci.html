The security page, with gitleaks in CI

Build log14 September 2026VF Empire

The security page went live on the evening of 14 September, wired into the nav, with a fix to the mirror script that copies source into dist/. It publishes the proof behind the products: signed releases with a 2-of-2 threshold across separated EU jurisdictions, reproducible builds from public source, a bug bounty from €500 to €25 000, a warrant canary refreshed every 30 days, and the Terms § 8 warranty enforceable in Malta.

The centrepiece is the audit table. As of 2026-09-14 it shows four public repositories scanned, 64 commits inspected across complete git history, about 7 MB of code and history bytes, and zero secrets detected. The rows name the repositories, among them snapit-desktop (35 commits), vf-privacy-kit (4) and vfmail-desktop (6), each with a link to verify the result live. The scanner is gitleaks v8.24.2, with a ruleset of around 150 patterns covering cloud provider keys, Stripe keys, GitHub and GitLab tokens, private keys, OAuth and JWT secrets and database URLs.

Four commits in the following half hour put the discipline into this repository itself. Gitleaks now runs at two gates: a pre-commit hook on the developer's machine, which refuses a commit that contains a secret, and a GitHub Actions workflow as the backstop, running on every push, every pull request and every Monday at 06:00 UTC against full history, with a finding blocking the merge. The workflow was then switched from the action wrapper to the gitleaks binary run directly, so it works the same on personal-account repositories, organisation-owned repositories and forks with no licence secret required. The README gained the security-scan badge, and the audit table gained house-styled CI pills.

The same signing and transparency-log mechanisms the page describes are what the Signing Infrastructure engagement builds for clients. The public repositories belong to SnapIT and VF Mail among others; the seven private ones, FileIT and Guardian Shield included, sit under the same gitleaks discipline until launch. The principles behind the page are on the software page.
