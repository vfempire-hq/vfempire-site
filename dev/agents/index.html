WHAT AN AGENT IS AT VF

Not a chatbot.
A tool that finishes work.

A VF agent is a single-purpose native binary that runs on your machine. You brief it, it executes, it hands back a concrete result. No conversation loop unless the job needs one. No memory of your work leaves the machine. And every agent you install joins the same local fleet, so a single input can reach across all of them.

P·01

You own it, forever

Buy it once, run it on your hardware, keep it working after we stop shipping updates. Every agent inherits the Permanence Guarantee: if VF ever ends a product, the source is released under an open licence within 90 days and the last signed build stays verifiable.

P·02

Sealed by architecture

Every agent inherits the VF PrivacyKit: sealed identity, sealed transport, at-rest encryption bound to your machine's keychain. Nothing readable by governments, ad-tech or us. Search queries and model calls go to whichever backend you point them at, using your key, not ours.

P·03

Bring your own model

Every agent talks to an OpenAI-compatible endpoint. That covers Ollama and LM Studio on your own hardware, or the cloud of your choice with your key: Anthropic, OpenAI, DeepSeek, Grok, Together. We sell the harness. You pick the engine.

P·04

Composable through a local bus

Install one agent, it works. Install two, they discover each other and route work between themselves through a local Unix-socket or named-pipe bus that never touches the network. Sections below show how Auto-Mate calls Re-Kon on the same machine, in the same flow, with no cloud in the path.

HOW THEY COMPOSE

One local bus,
two agents behaving as one.

Every VF agent writes a manifest on startup to ~/.vf/agents/. Every other agent reads that directory and knows which capabilities are available. Calls between them run over Unix domain sockets on Linux and macOS, or named pipes on Windows. Nothing on the network. Nothing that VF can see. The whole flow completes on your box.

Auto-Mate calls Re-Kon, in one keystroke

You press Ctrl+Space. Auto-Mate's floating input appears. You type: "everything filed by Meta in the EU in the last 90 days". Enter. 1. Auto-Mate classifies the intent as research. 2. Auto-Mate shows the preview: Route to Re-Kon, new research mission. 3. You press Enter to confirm. 4. Auto-Mate opens ~/.vf/re-kon/agent.sock. 5. Auto-Mate calls research.mission.new with your brief. 6. Re-Kon plans, dispatches, ingests, distils. 7. Re-Kon publishes mission.completed on the bus. 8. Auto-Mate opens the dossier in a preview panel. No cloud. No third party. No VF servers touched.

The same pattern extends to every future VF agent. VF Mail advertises mail.message.send. FileIT advertises tax.filing.submit. Auto-Mate discovers them, exposes them in its input, and routes work to them the same way.

HOUSE RULES · EVERY AGENT INHERITS

Six principles.
Non-negotiable across the fleet.

The same six house primitives that gate every VF product apply to every agent on the fleet. They are enforced in architecture, in the FSL-1.1-ALv2 licence, and in the Terms § 15 warranty. Any agent that cannot meet all six is not shipped under the VF name.

R·01

Local-first, on your hardware

The agent runs on your machine. Model calls and search calls use backends you configure, with your keys. Nothing routes through VF servers.

R·02

One-time purchase

Buy it once. No subscription. No seat resets. No auto-renewal. Founding pricing is honoured for the first tranche of buyers; standard pricing after.

R·03

Sealed at rest

Every artefact on disk is encrypted with a key derived from your OS keychain via Argon2id. Portable exports are PrivacyKit-sealed on request.

R·04

No telemetry, ever

No usage pings, no crash beacons, no "anonymous statistics". Optional signed-update checks can be disabled per install without losing features.

R·05

Reproducible builds

Every shipping binary is byte-for-byte reproducible from source. Third-party CI mirrors verify continuously. Signed updates land in a public transparency log.

R·06

Permanence Guarantee

If VF ends an agent, the full source is released under an open licence within 90 days, the last signed build stays verifiable, and the sealed format stays readable. Nothing you bought becomes a paperweight.

ASKED, ANSWERED

The questions
every buyer asks first.

What is a VF agent, precisely?

A single-purpose native binary that runs on the buyer's machine, ships with a hardware-bound perpetual licence and inherits the six house rules listed above. It has one job, does that job well, and composes with other VF agents through the local fleet bus. There is no cloud dependency and no telemetry.

Which agents are shipping first?

Re-Kon (A·01), a sovereign research scout that plans and executes research missions, and Auto-Mate (A·02), a floating-input agent that runs machine and browser tasks and routes anything else to the right specialist. Both are in spec-complete state, both are engineered to the same standard, both are one-time purchase.

How do the agents communicate with each other?

Through a local bus. Each agent writes a manifest to ~/.vf/agents/ on startup and opens a Unix domain socket on Linux and macOS or a named pipe on Windows. Calls are JSON-RPC 2.0 signed with a shared local secret. Nothing on the network. If a buyer disables the bus, each agent still works on its own.

What model backend can I use?

Any OpenAI-compatible endpoint. That covers local runtimes (Ollama, LM Studio, vLLM, llama.cpp) and cloud services with your own key (Anthropic, OpenAI, DeepSeek, Grok, Together, Fireworks). VF sells the harness, not the model. Buyers on strict data-sovereignty postures typically point the agent at a local Ollama.

Is the code open?

Yes. Every agent ships under the Functional Source License 1.1 with an Apache 2.0 change licence (FSL-1.1-ALv2). Read the source, audit it, self-host from day one. After two years each release converts automatically to Apache 2.0, so the code is permanently open even if VF disappears.

What happens if VF Empire ends an agent?

The Permanence Guarantee, written into Terms § 15 and enforceable in Malta courts, requires that within ninety days of any end-of-life announcement the full source is released under a permissive open licence, the last signed build stays verifiable in the public transparency log, and the sealed data format is documented so any conformant reader can extract your material.
